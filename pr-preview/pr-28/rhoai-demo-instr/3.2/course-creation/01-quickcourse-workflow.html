The QuickCourse Generation Workflow

Learning Objectives

After completing this module, you will be able to:

  • Set up a QuickCourse project using the course-starter-template

  • Design effective course structure using the course-design.md format

  • Use the /initialize-course-project skill to configure your repository

  • Generate complete course skeletons with /generate-course-structure

  • Develop content efficiently using Claude Code assistance

  • Export and publish your course to GitHub Pages and PDF

Introduction

This guide shows you how to use Claude Code to generate complete Red Hat QuickCourses for any product or platform. You’ll learn the proven 5-phase workflow that takes you from initial course design through publication.

The QuickCourse workflow applies to any Red Hat technology:

  • Platforms: OpenShift, Ansible Automation Platform, OpenStack, OpenShift AI

  • Products: RHEL, Satellite, Identity Management, Insights

  • Technologies: Kubernetes, containers, AI/ML, storage, networking

  • Solutions: Hybrid cloud, edge computing, DevOps, security

This workflow combines:

  • Structured design documents - Define learning objectives and pedagogical flow

  • Automated generation - Use Claude Code skills to create course skeletons

  • Interactive development - Work with Claude to write technical content

  • Quality publishing - Generate web and PDF outputs

The 5-Phase QuickCourse Workflow

The QuickCourse generation process follows a sequential, proven workflow:

Phase 0: Setup → Phase 1: Design → Phase 2: Initialize →
Phase 3: Generate → Phase 4: Develop → Phase 5: Publish

Each phase builds on the previous one, creating a systematic approach to course creation.

Phase 0: Workspace Setup

Prerequisites

Before starting, ensure you have:

  • Git installed and configured

  • Node.js and npm installed

  • Claude Code CLI installed

  • GitHub account (for template and publishing)

Clone the Course Template

The course-starter-template provides the foundation for all QuickCourses:

# Visit GitHub template repository
# https://github.com/RedHatQuickCourses/course-starter-template

# Click "Use this template" → Create new repository
# Name your repository (e.g., "gpu-enablement-course")
# Set visibility to Public

# Clone your new repository
git clone https://github.com/RedHatQuickCourses/<your-course-name>
cd <your-course-name>

Launch Claude Code

Open the repository in your code editor and start Claude Code:

# Open in VS Code or your preferred editor
code .

# In the integrated terminal, launch Claude Code
claude

All /commands and conversational prompts mentioned in this guide are typed directly into the Claude Code terminal prompt. Claude acts as your pair-programmer inside the repository.

Understanding the Template Structure

The starter template includes:

course-starter-template/
├── .agents/                    # Claude skills directory
│   └── skills/                 # Course generation skills
├── antora.yml                  # Course metadata (DO NOT MODIFY initially)
├── antora-playbook.yml         # Build configuration (DO NOT MODIFY)
├── course-init.sh              # Initialization script
├── modules/                    # Course content (will be generated)
├── modules.bfx/                # Business Features templates
├── package.json                # Build dependencies
├── prompts/                    # Design documents go here
├── templates/                  # Section templates
└── USAGEGUIDE.adoc             # AsciiDoc reference

Never manually modify these files:

  • antora-playbook.yml - Build configuration

  • *.sh scripts - Automation scripts

  • package.json - Dependencies

  • ui-assets/, ui-bundle/, supplemental-ui/ - UI components

Skills will manage these files for you.

Phase 1: Course Design

Design Document Purpose

The course design document (prompts/course-design.md) drives the entire generation process. It defines:

  • Course goals - What learners will accomplish

  • Target audience - Who should take the course

  • Learning objectives - Major competencies (become chapters)

  • Sections - Individual topics within objectives

  • Session types - Presentation, Lab, Quiz, etc.

Design Document Template

Create prompts/course-design.md with this structure:

![Course Banner Image](../images/banner.png)

# Course Title

One-sentence tagline describing the course.

# COURSE GOAL

Single paragraph describing what learners will accomplish by completing
this course. Focus on business value and practical outcomes.

Example: "By completing this course, system administrators will be able to
deploy and configure Red Hat Ansible Automation Platform on OpenShift,
enabling self-service automation workflows that reduce deployment time
from hours to minutes while maintaining enterprise security and compliance."

# TARGET AUDIENCE

Who should take this course:

- **Job roles**: OpenShift administrators, Platform engineers, System architects
- **Experience level**: Intermediate to advanced
- **Responsibilities**: Managing enterprise virtualization workloads

# PREREQUISITES

This course assumes learners have:

* Familiarity with OpenShift administration and basic concepts
* Experience with command-line tools (oc, kubectl)
* Basic understanding of virtualization concepts
* Access to an OpenShift cluster (recommended but not required)

# COURSE DESIGN

| Learning Objective / Section | Session Type |
|------------------------------|--------------|
| **LEARNING OBJECTIVE #1: Deploy OpenShift Virtualization** | |
| Understand OpenShift Virtualization architecture and components | Presentation |
| Install and configure OpenShift Virtualization operator | Lab |
| Verify installation and create first virtual machine | Lab |
| **LEARNING OBJECTIVE #2: Manage virtual machine workloads** | |
| Virtual machine templates and customization | Presentation |
| Create and configure VM templates for different workloads | Lab |
| Manage VM networking and storage | Lab |
| Troubleshooting common VM deployment issues | Lab |
| **LEARNING OBJECTIVE #3: Advanced features and production operations** | |
| Live migration, high availability, and backup strategies | Presentation |
| Configure live migration and test failover scenarios | Lab |
| Implement backup and disaster recovery for VMs | Lab |
| Virtual machine management knowledge check | Quiz |

Design Best Practices

Learning Objectives (Chapters):

  • Quantity: 3-6 objectives per course (optimal: 4-5)

  • Progression: Build from basic → intermediate → advanced

  • Format: "LEARNING OBJECTIVE #N: Action verb + specific skill"

  • Focus: Each objective = one major competency

Sections (Pages within chapters):

  • Quantity: 2-5 sections per objective

  • Duration: Each section = 5-15 minutes

  • Flow: Follow pedagogical progression:

    1. Presentation/Lecture - Introduce concepts and theory

    2. Lab - Hands-on practice and application

    3. Quiz - Knowledge validation and assessment

Session Types:

  • Presentation - Slideshow-style with diagrams and screenshots

  • Lecture - Text-heavy explanatory content

  • Lab - Step-by-step hands-on activities with commands

  • Quiz - Multiple choice or interactive knowledge checks

Start small: For your first QuickCourse, aim for 3 learning objectives with 2-3 sections each. This creates a focused, completable course in 1-2 weeks.

Phase 2: Initialize Course Project

Purpose

The initialization phase configures your repository for the specific course type and lab environment. This must be completed before generation.

The /initialize-course-project Skill

In your Claude Code terminal, invoke the initialization skill:

/initialize-course-project

The skill will ask three questions:

Question 1: Course Type

What course type? (bfx/hol)

Options:

  • bfx (Business Features/QuickCourses) - Modular structure with chapters

    • Best for: Product features, administration, operations

    • Structure: Multiple learning objectives, progressive flow

    • Use this for most enablement content

  • hol (Hands-On Labs) - Lab-centric structure

    • Best for: Pure hands-on workshops, guided exercises

    • Structure: Simplified, focused on lab activities

Golden Path: Choose bfx for standard Red Hat QuickCourses. This provides the modular, chapter-based structure best suited for rapid enablement.

Question 2: Lab Environment

What lab environment? (demo/role/other)

Options:

  • demo - Self-contained demos, no external lab required

  • role - Uses Red Hat Online Learning (ROLE) classroom labs

  • other - Custom environments (self-provisioned, cloud, etc.)

If unsure, select other to keep prerequisites flexible. You can document specific requirements later.

Question 3: Course Title

What is the course title?

Provide the full course title. Examples:

User: OpenShift Virtualization Administration
User: Advanced Cluster Management for Kubernetes
User: Ansible Automation Platform on OpenShift
User: Red Hat Satellite 6 Administration

What Initialization Does

The skill performs these actions:

  1. Runs course-init.sh script with your selections

  2. Updates antora.yml with course metadata

  3. Configures course type (bfx/hol) structure

  4. Sets lab environment prerequisites

  5. Cleans up template files

  6. Installs npm dependencies (npm install)

  7. Verifies build works (npm run build)

  8. Optionally starts watch mode

  9. Deletes course-init.sh (one-time use)

Example Workflow

User: /initialize-course-project

Claude: What course type? (bfx/hol)
User: bfx

Claude: What lab environment? (demo/role/other)
User: role

Claude: What is the course title?
User: OpenShift Virtualization Administration

Claude: [Initializing course...]
  ✅ Running course-init.sh with: bfx role
  ✅ Updated antora.yml with title and course type
  ✅ Installed dependencies (npm install)
  ✅ Build verified successfully
  ✅ Deleted course-init.sh

  Course initialized! Ready for Phase 3.

This skill runs only once. After completion, course-init.sh is deleted. You cannot re-initialize without starting from a fresh template clone.

Phase 3: Generate Course Structure

Purpose

This phase auto-generates the complete course skeleton from your design document, creating all directories, files, and navigation.

Prerequisites

Before running generation:

  • ✅ Phase 2 completed (course initialized)

  • ✅ prompts/course-design.md exists with proper format

  • ⚠️ Watch mode stopped if running (skill will prompt)

The /generate-course-structure Skill

In your Claude Code terminal:

/generate-course-structure

What Generation Does

The skill performs these operations:

  1. Parses prompts/course-design.md to extract structure

  2. Creates chapter directories for each learning objective

  3. Generates section files with appropriate templates

  4. Builds navigation files (nav.adoc per chapter)

  5. Updates antora.yml with chapter references

  6. Generates "What’s Next" transitions between sections

  7. Cleans up example chapters (chapter1, chapter2, chapter3)

  8. Optionally restarts watch mode

Generated Structure

For each Learning Objective, the skill creates:

modules/ch{N}-{keyword}/
├── nav.adoc                          # Chapter navigation
├── pages/
│   ├── index.adoc                    # Chapter landing page
│   ├── s1-{keyword}.adoc             # Section 1 (Presentation/Lecture)
│   ├── s2-{keyword}-lab.adoc         # Section 2 (Lab)
│   ├── s3-{keyword}-quiz.adoc        # Section 3 (Quiz)
│   └── ...                           # Additional sections
└── images/                           # Placeholder for chapter images

Additionally, the ROOT module gets updated:

modules/ROOT/pages/index.adoc         # Course overview page

Naming Conventions

The skill uses intelligent keyword extraction:

Chapters:

  • Format: ch{N}-{keyword} (e.g., ch1-installation, ch2-configuration, ch3-operations)

  • Number: From learning objective number

  • Keyword: Main concept extracted from objective text

  • Padding: Zero-padded if 10+ chapters (ch01, ch02, …​)

  • Examples:

    • ch1-virtualization-deploy

    • ch2-acm-install

    • ch3-satellite-lifecycle

Sections:

  • Format: s{N}-{keyword}[-suffix].adoc

  • Examples:

    • s1-nvidia-operator-lab.adoc (Lab)

    • s2-verify-gpu.adoc (Presentation)

    • s3-gpu-quiz.adoc (Quiz)

  • Suffixes:

    • Lab → -lab.adoc

    • Quiz → -quiz.adoc

    • Presentation/Lecture → .adoc

Phase 4: Develop Content

Overview

With the skeleton generated, Phase 4 focuses on filling in actual course content. This is where you work with Claude Code to write presentations, labs, and quizzes.

Start Watch Mode (Critical)

Before making any changes, start real-time preview:

Use two separate terminal windows (NOT the Claude Code terminal):

Terminal 1 - Watches for changes and rebuilds:

npm run watch:adoc

Terminal 2 - Serves the local site:

npm run serve

Then open your browser to http://localhost:8080 to preview the course.

Content Development Workflow

Work chapter-by-chapter, section-by-section:

  1. Update chapter index (modules/ch1-keyword/pages/index.adoc)

    • Refine chapter goal

    • Add chapter introduction

    • Remove WARNING: Not started yet when complete

  2. Fill section content (work sequentially)

    • Start with section 1, proceed in order

    • Follow template structure

    • Add content between placeholders

  3. Add images

    • Place in modules/ch{N}-keyword/images/

    • Reference: image::screenshot.png[Alt text]

  4. Test labs manually

    • Verify all commands work

    • Document actual outputs

    • Add troubleshooting notes

Using Claude Code to Write Content

You don’t need to write all AsciiDoc manually! Ask Claude Code to assist:

Example prompts:

Work with Claude conversationally: Describe what you need, paste rough notes or commands, and let Claude format it into proper AsciiDoc. You provide the technical knowledge; Claude handles the formatting.

  name: hco-operatorhub
  namespace: openshift-cnv

  source: redhat-operators
  sourceNamespace: openshift-marketplace
  name: kubevirt-hyperconverged
  channel: "stable"
EOF

= Quiz: Virtualization Fundamentals Knowledge Check

_Estimated reading time: *{time_estimate} minutes*._

Objective::
Validate understanding of OpenShift Virtualization architecture and deployment.

== Questions

1. **What is the primary benefit of OpenShift Virtualization?**
+
a. It replaces the need for containers entirely
+
b. It allows running VMs and containers on a unified platform
+
c. It provides better performance than traditional hypervisors
+
d. It eliminates the need for storage configurations
+
**Answer: b** - OpenShift Virtualization enables running virtual machines
alongside container workloads on the same OpenShift platform, eliminating
the need for separate infrastructure.

2. **Which technology is OpenShift Virtualization based on?**
+
a. VMware ESXi
+
b. KVM directly
+
c. KubeVirt
+
d. Docker
+
**Answer: c** - OpenShift Virtualization is based on the KubeVirt project,
which brings VM capabilities to Kubernetes.

3. **What command verifies that hardware virtualization is enabled?**
+
a. `oc get virtualization`
+
b. `cat /proc/cpuinfo | grep -E 'vmx|svm'`
+
c. `virtctl version`
+
d. `oc describe node`
+
**Answer: b** - Checking for `vmx` (Intel) or `svm` (AMD) flags in
/proc/cpuinfo confirms hardware virtualization support.

Troubleshooting






Build Fails After Generation




Symptom: npm run build produces errors






Solutions:






    

  • 

    Check antora.yml for syntax errors (YAML indentation)
    

    • 

  • 

    Verify all xref targets exist (typo in filename?)
    

    • 

  • 

    Look for malformed AsciiDoc (unclosed blocks, invalid attributes)
    

    • 

  • 

    Run debug build:
    

    

    

    npx antora --log-level=debug antora-playbook.yml
    

    

    

    • 









Navigation Not Showing Sections




Symptom: Chapter appears but sections don’t show in navigation






Solutions:






    

  • 

    Verify modules/ch{N}-keyword/nav.adoc exists
    

    • 

  • 

    Check xref format (should be): ** xref:s1-section.adoc[]
    

    • 

  • 

    Ensure filenames match exactly (case-sensitive)
    

    • 

  • 

    Rebuild: npm run build
    

    • 









Images Not Displaying




Symptom: Broken image links in rendered site






Solutions:






    

  • 

    Verify image is in modules/ch{N}-keyword/images/
    

    • 

  • 

    Use correct syntax: image::filename.png[] (NOT Markdown ![]())
    

    • 

  • 

    Check filename matches exactly (case-sensitive)
    

    • 

  • 

    Hard refresh browser (Cmd+Shift+R / Ctrl+Shift+F5)
    

    • 









Watch Mode Not Rebuilding




Symptom: Changes don’t trigger rebuild in browser






Solutions:






    

  • 

    Kill and restart npm run watch:adoc in Terminal 1
    

    • 

  • 

    Verify you’re editing files in modules/ directory
    

    • 

  • 

    Try manual build: npm run build
    

    • 

  • 

    Check for syntax errors in AsciiDoc
    

    • 









PDF Generation Fails




Symptom: /generate-pdf skill errors






Solutions:






    

  • 

    Install Ruby: brew install ruby (macOS) or apt install ruby (Linux)
    

    • 

  • 

    Install gem manually: gem install asciidoctor-pdf
    

    • 

  • 

    Install PDF extension: npm install @antora/pdf-extension
    

    • 

  • 

    Check for AsciiDoc syntax errors (PDF renderer is stricter than HTML)
    

    • 













Best Practices Summary






Design Phase




    

  • 

    ✅ Start with clear learning objectives (4-6 is optimal)
    

    • 

  • 

    ✅ Balance theory (Presentation) and practice (Lab)
    

    • 

  • 

    ✅ Include knowledge checks (Quiz) after key concepts
    

    • 

  • 

    ✅ Keep sections focused and short (5-15 minutes each)
    

    • 

  • 

    ✅ Design for progressive learning (simple → complex)
    

    • 









Development Phase




    

  • 

    ✅ Work sequentially (complete chapter 1 before chapter 2)
    

    • 

  • 

    ✅ Let Claude write the boilerplate AsciiDoc; you provide technical facts
    

    • 

  • 

    ✅ Test all lab instructions yourself
    

    • 

  • 

    ✅ Use watch mode (Terminal 1) and serve mode (Terminal 2) for real-time preview
    

    • 

  • 

    ✅ Update time estimates with reading-time.sh
    

    • 

  • 

    ✅ Add images generously (diagrams, screenshots, flowcharts)
    

    • 









Technical Quality




    

  • 

    ✅ Use AsciiDoc syntax correctly (see USAGEGUIDE.adoc)
    

    • 

  • 

    ✅ Keep code blocks short and focused
    

    • 

  • 

    ✅ Highlight important output in command examples (bold user input)
    

    • 

  • 

    ✅ Test all xref links
    

    • 

  • 

    ✅ Use NOTE, WARNING, TIP callouts appropriately
    

    • 









Content Quality




    

  • 

    ✅ Write for the target audience level
    

    • 

  • 

    ✅ Define technical terms on first use
    

    • 

  • 

    ✅ Provide context (why, not just how)
